Audited: rank-tracker crawl against the production domain, plus a full read of this repository.
Nothing below is assumed; each item shows how it was measured.

## What was verified, and how

### 1. The sitemap is hand-maintained and drifted from the app
`grep -c '<loc>'` on the production sitemap returns 282. The router defines 39 static routes, 127 tool
slugs and 77 blog posts. Cross-checking every production URL against the source produced 100 URLs with no
route and no content record — including all locale paths (`/de/…`, `/fr/…`, `/it/…`) and pages such as
`/image-optimization-masterclass`, `/image-format-benchmarks`, `/pdf-compression-guide`,
`/add-text-to-image`, `/ai-image-generator` and several `/blog/…` slugs that do not exist anywhere in
`src/`. Full list: `seo/phantom-urls.txt`.

**Fix shipped:** `scripts/generate-sitemap.mjs` builds the sitemap from `src/App.tsx`,
`src/data/toolsSEOData.ts`, `src/data/blogData.ts`, `src/pages/BlogPost.tsx` and the content modules.
Add it to the build so it can never drift again:

```json
"scripts": {
  "build": "node scripts/generate-sitemap.mjs && vite build"
}
```

### 2. Every URL is client-rendered, so first responses are thin
Fetching 25 sitemap URLs and stripping `<script>`/`<style>` left fewer than 80 words of text in all 25.
Titles and meta tags are unique per URL, so the pages can rank, but indexing depends entirely on
Googlebot rendering the JavaScript.

**Fix:** pre-render the homepage, `/all-tools`, the category hubs, the ten highest-traffic tool pages and
all blog posts. See `seo/implementation/fix-soft-404-and-rendering.md`.

### 3. Unknown URLs return 200
`/this-page-does-not-exist-xyz` returns HTTP 200 because every path is rewritten to `index.html`.
Google reports these as soft 404s and they consume crawl budget. `DynamicToolPage` already redirects
unknown slugs to `/404`, but the server still answers 200.

**Fix:** return a real 404 status for unmatched paths at the host level, and add a `noindex` meta on the
404 view.

### 4. Two domains serve the same site
`https://multitoolsa.com` and `https://multitoolsa.sudhiryadav7.com.np` both answer 200 with the same
application. `og:url` points at the `.com` domain, and there is a canonical tag, but a 200 mirror still
splits signals and gives reviewers two copies to compare.

**Fix:** see `seo/implementation/cloudflare-mirror-redirect.md`.

### 5. Duplicate content comes from the content pipeline, not the tools
The repository contains `premiumSEOContentBatch1` through `Batch8` plus `premiumSEOContent.ts`,
`comprehensiveSEOContent.ts`, `additionalSEOContent.ts` and `categorySEOData.ts`. These produce page
bodies by substituting the tool name into shared paragraphs. Google's spam policy describes this as
scaled content abuse, and AdSense reviewers reject it as low-value content.

**Fix:** publish the unique copy in `seo/tools/` for the highest-traffic pages first, then delete the
batch modules rather than layering new text on top of them.

### 6. `ads.txt` and the AdSense meta tag are correct
`public/ads.txt` contains `google.com, pub-3929937587842220, DIRECT, f08c47fec0942fa0` and the
verification meta is in `index.html`. Money and verification are not the blockers; content quality,
policy pages and the mirror domain are.

## Order of work

1. Add the generated sitemap and submit it in Search Console.
2. Deploy the mirror-domain 301 and the real-404 handling.
3. Publish the rewritten tool copy for the ten highest-traffic tools; delete the batch modules.
4. Submit the sitemap again, request indexing on the rewritten URLs.
5. Apply for AdSense review.
